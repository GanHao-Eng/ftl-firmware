# NVMe SSD固件详细设计文档

## 1. 项目概述

### 1.1 项目定位

本项目是一套完整的NVMe SSD固件参考实现，涵盖从底层NAND闪存抽象、FTL闪存转换层核心算法、NVMe控制器，到前端NVMe/TCP目标端协议栈的完整技术栈。项目实现与Linux内核nvme-tcp驱动的真实对接，支持nvme-cli、fio、dd等标准存储工具的功能验证与性能测试。

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| 模块化架构 | 7层分层设计，模块间低耦合高内聚，接口清晰 |
| 协议真实对接 | NVMe/TCP协议栈与Linux内核驱动完整对接，非模拟协议 |
| 高可靠性 | 掉电保护、ECC纠错、读干扰处理、数据保留、坏块管理 |
| 算法完整性 | 6种GC算法对比、动态/静态磨损均衡、三种映射模式 |
| 可扩展性 | 支持UFS协议栈扩展、OS抽象层支持RTOS移植 |
| 可维护性 | Doxygen注释、CI自动化测试、统一编码规范 |

### 1.3 技术栈

- **编程语言**：C99
- **构建系统**：GNU Make
- **目标平台**：Linux用户态（可移植到嵌入式RTOS）
- **协议对接**：Linux内核nvme-tcp驱动
- **测试工具**：nvme-cli、fio、dd、tcpdump
- **CI**：GitHub Actions

## 3. 模块详细设计

### 3.1 NAND闪存抽象层

#### 3.1.1 物理参数配置

| 参数 | 值 | 说明 |
|------|-----|------|
| 页大小 | 4096字节 | NAND物理页大小 |
| 块大小 | 256页/块 | 1024KB/块 |
| 总块数 | 128块 | 128MB原始容量 |
| 颗粒类型 | TLC | 3位/单元，擦写寿命1000次 |
| 初始坏块比例 | 3% | 约3-4个初始坏块 |
| 预留块 | 8块 | 用于坏块替换 |
| OOB大小 | 16字节 | magic/crc32/ecc/bad_block_mark |

#### 3.1.2 核心数据结构

```c
/* 物理块控制结构体 */
typedef struct {
    block_state_t state;               /* 块状态：FREE/USED/BAD */
    uint32_t erase_count;              /* 擦写次数（磨损计数） */
    uint32_t valid_page_cnt;           /* 有效页数量 */
    uint32_t read_count;               /* 读取次数（读干扰检测） */
    uint8_t  need_reclaim;             /* 读干扰标记：1=需要回收 */
    bad_block_type_t bad_type;         /* 坏块类型 */
    uint8_t  page_valid[256];          /* 页有效位图 */
} phy_block_t;

/* OOB区域结构（16字节） */
typedef struct {
    uint32_t magic;        /* OOB魔数："OOB1" = 0x4F4F4231 */
    uint32_t crc32;        /* CRC32校验值 */
    uint32_t ecc;          /* ECC校验值（汉明码） */
    uint8_t  bad_block_mark;  /* 坏块标记：0xFF=正常 */
    uint8_t  reserved[3];     /* 预留 */
} nand_oob_t;
```

#### 3.1.3 页布局

```
物理页布局（每页4112字节）：
┌──────────────────────────┬──────────────┐
│      数据区 (4096字节)    │  OOB (16字节) │
└──────────────────────────┴──────────────┘

OOB布局：
┌──────────┬──────────┬──────────┬──────┬──────────┐
│ magic(4) │ crc32(4) │  ecc(4)  │ mark │ reserved │
└──────────┴──────────┴──────────┴──────┴──────────┘
```

#### 3.1.4 核心接口

| 接口 | 功能 | 关键逻辑 |
|------|------|---------|
| nand_init | 初始化NAND介质 | 全新介质用"w+b"创建，恢复模式用"r+b"保留数据；扫描OOB重建页状态 |
| nand_page_read | 读取物理页 | 检查页有效标记→读取数据→读取OOB→ECC校验纠正→读干扰检测 |
| nand_page_write | 写入物理页 | 检查块状态→检查页未写入→写入数据→计算ECC→写入OOB→更新页有效标记 |
| nand_block_erase | 擦除物理块 | 检查块状态→擦除（清零文件区域）→重置页有效标记→磨损计数+1→高磨损概率变坏块 |
| nand_inject_retention_errors | 数据保留错误注入 | 遍历有效页→按错误率随机翻转位→写回数据（不更新OOB的ECC） |

#### 3.1.5 ECC纠错机制

采用(7,4)汉明码编解码：
- **编码**：4位数据 → 7位码字（3个校验位），可纠正1位错误，检测2位错误
- **写入**：对整页数据计算ECC校验值，存入OOB的ecc字段
- **读取**：重新计算ECC，与OOB存储值比较
  - 相同：无错误
  - 不同：逐位翻转尝试定位错误（1位错误可纠正），多位错误返回UNCORRECTABLE

#### 3.1.6 读干扰处理

- 每次读取物理页时，递增该块的read_count
- 当read_count超过阈值（100000次），标记need_reclaim=1
- 后台任务检测到need_reclaim标记，触发read reclaim：将该块有效页搬迁到新块，擦除旧块

#### 3.1.7 掉电恢复模式

- nand_init时检测介质文件是否存在
  - 不存在：全新介质，用"w+b"创建，随机生成初始坏块
  - 存在：恢复模式，用"r+b"打开保留数据，不随机生成坏块（坏块出厂固定）
- 恢复模式下扫描所有页的OOB区域，通过magic字段重建page_valid位图和块状态

### 3.2 FTL闪存转换层

#### 3.2.1 核心参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 总逻辑页数 | 22937 | 128块×256页×70%（预留30%用于OP和坏块） |
| 映射模式 | 页映射/块映射/混合映射 | 可配置 |
| GC算法 | 6种 | Greedy/Cost-Benefit/CAT/Windowed/d-Choices/FRA |
| OP比例 | 30% | 过度配置空间，用于GC和坏块替换 |

#### 3.2.2 核心数据结构

```c
/* FTL设备全局状态 */
typedef struct {
    bool is_initialized;              /* 初始化标志 */
    ftl_map_mode_t map_mode;         /* 映射模式 */
    gc_algo_t gc_algo;               /* GC算法 */
    uint32_t *l2p_table;             /* L2P映射表：逻辑页→物理页 */
    uint32_t *reverse_map;           /* 反向映射：物理页→逻辑页 */
    uint32_t cur_write_block;        /* 当前写入块 */
    uint32_t cur_write_page;         /* 当前写入页位置 */
    uint64_t host_write_pages;       /* 主机写入页数统计 */
    uint64_t nand_write_pages;       /* NAND实际写入页数（含GC搬迁） */
    uint32_t gc_count;               /* GC触发次数 */
    uint32_t trim_count;             /* TRIM操作次数 */
} ftl_dev_t;

/* FTL元数据快照头（用于PLP掉电保护） */
typedef struct {
    uint32_t magic;            /* 魔数："FTL1" = 0x46544C31 */
    uint32_t version;          /* 版本号 */
    uint32_t checksum;         /* 校验和 */
    uint32_t host_write_pages; /* 主机写入页数 */
    uint32_t nand_write_pages; /* NAND写入页数 */
    uint32_t gc_count;         /* GC次数 */
    uint32_t cur_write_block;  /* 当前写入块 */
    uint32_t cur_write_page;   /* 当前写入页 */
} ftl_meta_header_t;
```

#### 3.2.3 L2P映射机制

- **页映射**：每个逻辑页独立映射到物理页，L2P表大小=22937×4字节≈90KB
- **块映射**：逻辑块→物理块，块内偏移不变，映射表小但灵活性差
- **混合映射**：热数据页映射，冷数据块映射，平衡性能和空间

映射查找：`物理页号 = l2p_table[逻辑页号]`，O(1)时间复杂度。

#### 3.2.4 写入流程

```
主机写入请求(LPN, 数据)
    │
    ▼
检查LPN是否已映射
    │
    ├─ 已映射 → 标记旧物理页无效（valid_page_cnt--）
    │
    ▼
分配新物理页 ftl_alloc_phy_page()
    │
    ├─ 当前块有空闲页 → 直接分配
    └─ 当前块满 → 选择新空闲块 → 触发GC（如果空闲块不足）
    │
    ▼
写入NAND nand_page_write(PPN, 数据)
    │
    ▼
更新L2P映射 l2p_table[LPN] = PPN
    │
    ▼
更新统计 host_write_pages++
```

#### 3.2.5 读取流程

```
主机读取请求(LPN)
    │
    ▼
检查LPN是否映射 l2p_table[LPN] != INVALID
    │
    ├─ 未映射 → 返回RET_ERR_NOT_MAPPED
    │
    ▼
获取物理页号 PPN = l2p_table[LPN]
    │
    ▼
读取NAND nand_page_read(PPN, 缓冲区)
    │
    ├─ 遇到坏块 → 触发坏块替换 → 数据可能丢失
    └─ ECC检测到错误 → 自动纠正1位错误 / 多位错误返回
    │
    ▼
返回数据
```

#### 3.2.6 GC垃圾回收

**6种GC算法对比**：

| 算法 | 选择策略 | 优点 | 缺点 |
|------|---------|------|------|
| Greedy | 有效页最少的块 | 搬迁量最小，WAF最低 | 未考虑擦写次数，磨损不均 |
| Cost-Benefit | (1-有效率)/擦写次数 | 平衡磨损和搬迁量 | 计算稍复杂 |
| CAT | 冷热分类+有效率 | 考虑数据热度 | 需要维护热度信息 |
| Windowed | 滑动窗口内最优 | 避免局部最优 | 窗口大小影响效果 |
| d-Choices | 随机选d个块取最优 | 平衡性能和质量 | d值需调优 |
| FRA | 基于帧的自适应 | 自适应工作负载 | 实现复杂 |

**GC触发条件**：空闲块数量低于阈值（预留块+少量空闲块）。

**GC执行流程**：
1. 选择 victim 块（根据GC算法）
2. 遍历该块有效页，读取数据
3. 将有效页写入新的空闲块
4. 更新L2P映射表
5. 擦除victim块
6. 更新统计：gc_count++，nand_write_pages += 搬迁页数

#### 3.2.7 磨损均衡

- **动态磨损均衡**：写入时优先选择擦写次数少的空闲块
- **静态磨损均衡**：定期检查冷数据块（擦写次数少且数据不常更新），将其搬迁到高磨损块，让低磨损块接收新写入
- 目标：所有块的擦写次数尽量均匀，延长SSD整体寿命

#### 3.2.8 坏块管理

- **初始坏块**：出厂时随机生成（TLC约3%），nand_init时标记
- **磨损坏块**：擦写次数超过阈值后，概率性变为坏块
- **坏块替换**：写入/读取遇到坏块时，从预留块池分配新块替换
- **坏块表**：维护坏块列表，GC和分配时跳过坏块

#### 3.2.9 掉电保护(PLP)

**快照结构**：
```
快照文件布局：
┌──────────────────┬──────────────────────┐
│ 元数据头(32字节)  │  L2P映射表(约90KB)   │
└──────────────────┴──────────────────────┘
```

**保存时机**：
- 主循环每5000次循环保存一次
- 固件退出前保存一次

**恢复流程**：
1. ftl_init初始化L2P表为全INVALID
2. 调用ftl_load_snapshot读取快照文件
3. 校验magic和checksum
4. 恢复L2P映射表和统计信息
5. 重建反向映射表
6. NAND层扫描OOB重建页有效状态

#### 3.2.10 TRIM/Dataset Management

- 主机发送TRIM命令，指定要释放的LBA范围
- FTL层将对应LPN标记为未映射（l2p_table[LPN] = INVALID）
- 对应物理页的有效计数递减，可被GC回收
- 读取已TRIM的LPN返回NOT_MAPPED或全零（取决于实现）

### 3.3 NVMe控制器层

#### 3.3.1 职责

- Admin命令处理：Identify、Get Log Page、Set Features、Get Features、Keep Alive、Create I/O Queue等
- I/O命令分发：Read、Write、Write Zeroes、Flush、Dataset Management等
- 队列管理：Admin队列 + 多个I/O队列
- 寄存器映射：Controller Capability、Version、Config、Status等

#### 3.3.2 命令处理流程

```
NVMe命令(从TCP层接收)
    │
    ▼
判断队列类型
    │
    ├─ Admin队列 → Admin命令处理
    │     ├─ Identify → 返回Controller/Namespace信息
    │     ├─ Get Log Page → 返回SMART/错误日志
    │     ├─ Set Features → 配置参数
    │     ├─ Create I/O CQ/SQ → 创建I/O队列
    │     └─ Keep Alive → 保活
    │
    └─ I/O队列 → I/O命令处理
          ├─ Read → ftl_read → nand_page_read → 返回数据
          ├─ Write → ftl_write → nand_page_write
          ├─ Write Zeroes → 写入全零数据
          ├─ Flush → 同步（模拟器无缓存，直接返回）
          └─ Dataset Management → ftl_trim
    │
    ▼
构造完成队列条目(CQE)
    │
    ▼
通过TCP层发送CapsuleResp给主机
```

### 3.4 NVMe/TCP目标端协议层

#### 3.4.1 协议栈层次

```
NVMe over TCP 协议栈：
┌─────────────────────────────────┐
│  NVMe命令层 (Admin/I/O命令)      │
├─────────────────────────────────┤
│  NVMe Fabrics层 (Connect/Property)│
├─────────────────────────────────┤
│  PDU层 (CapsuleCmd/CapsuleResp/  │
│         H2CData/C2HData/R2T)     │
├─────────────────────────────────┤
│  TCP传输层 (Socket连接/数据收发)   │
└─────────────────────────────────┘
```

#### 3.4.2 PDU类型

| PDU类型 | 方向 | 功能 |
|---------|------|------|
| ICReq/ICResp | H→D/D→H | 初始化握手，协商参数 |
| CapsuleCmd | H→D | 封装NVMe命令（含或不含数据） |
| CapsuleResp | D→H | 命令完成响应（含完成队列条目） |
| H2CData | H→D | 主机到设备数据（写命令数据） |
| C2HData | D→H | 设备到主机数据（读命令数据） |
| R2T | D→H | 请求发送数据（设备请求主机发送写数据） |

#### 3.4.3 连接建立流程

```
主机                          设备
  │                            │
  │── TCP连接(SYN) ──────────→│
  │←── TCP连接(ACK) ───────────│
  │                            │
  │── ICReq(初始化握手) ──────→│
  │                            │  解析ICReq，验证PDU格式
  │                            │  分配连接资源
  │←── ICResp(握手响应) ───────│
  │                            │
  │── Connect(Fabric命令) ────→│
  │                            │  解析Connect，提取SUBNQN/QID
  │                            │  QID=0 → Admin队列
  │                            │  QID>0 → I/O队列
  │←── Connect响应 ────────────│
  │                            │
  │── Admin命令(Identify等) ──→│
  │←── Admin响应 ───────────────│
  │                            │
  │── Create I/O CQ/SQ ───────→│
  │←── 响应 ────────────────────│
  │                            │
  │── I/O Read/Write ─────────→│
  │←── 数据/响应 ───────────────│
```

#### 3.4.4 关键兼容性问题（已解决）

| 问题 | 现象 | 根因 | 解决方案 |
|------|------|------|---------|
| CapsuleResp phase bit | 主机认为响应无效 | phase bit未正确翻转 | 每次发送响应时翻转phase bit |
| Identify字段偏移 | 主机解析Identify数据错误 | LBAF等字段偏移不对 | 对照NVMe规范逐字段核对偏移 |
| LBAF布局 | 主机识别块大小错误 | LBAF格式字段顺序不对 | 按规范：LBAF0=4KB，LSZ=12(2^12=4096) |
| Get Log Page与I/O Read冲突 | opcode冲突导致命令路由错误 | Get Log Page opcode与Read相同 | Admin队列和I/O队列分离处理 |
| Connect QID提取 | I/O队列创建失败 | QID从Connect inline data偏移提取错误 | 对照NVMe-oF规范提取QID字段 |

### 3.5 vhost-user NVMe后端协议层

#### 3.5.1 设计目标

vhost-user NVMe 后端使固件可以作为 QEMU 虚拟机的 NVMe 设备后端运行。与 NVMe/TCP 模式通过网络协议栈对接不同，vhost-user 模式通过 Unix socket + 共享内存实现低延迟数据传输，QEMU 直接模拟 PCIe NVMe 设备，虚拟机内使用标准 nvme 驱动即可识别。

#### 3.5.2 协议架构

```
┌─────────────────────────────────────────────────────────┐

│  ┌─────────────────────────────────────────────────────┐ │
```

#### 3.5.4 运行时数据路径

**命令提交路径（QEMU → 固件）：**
1. QEMU 将 nvme_command_t(64字节) 写入 available ring 描述符指向的缓冲区
2. QEMU 写门铃寄存器（SET_CONFIG，偏移 0x1000+qid*4）
3. 后端检测门铃变化，从 available ring 取描述符
4. 后端读取 nvme_command_t，根据队列ID分发到 Admin 或 I/O 处理

**数据传输路径：**
- Read 命令：后端从 FTL/NAND 读取数据，通过 PRP 指针写入 Guest 共享内存
- Write 命令：后端通过 PRP 指针从 Guest 共享内存读取数据，写入 FTL/NAND
- PRP 解析：PRP1 是首页地址（含页内偏移），PRP2 页对齐时是 PRP 列表指针，否则是第二页地址

**命令完成路径（固件 → QEMU）：**
1. 后端将 nvme_completion_t(16字节) 写入 available ring 描述符缓冲区的偏移64处
2. 后端更新 used ring，写入描述符索引和数据长度
3. 后端写 call eventfd（写入1），QEMU 检测到 eventfd 可读后触发虚拟机中断
4. Guest nvme 驱动从 used ring 读取完成条目

#### 3.5.5 共享内存管理

- SET_MEM_TABLE 消息携带最多 VHOST_USER_MAX_MEM_REGIONS(16) 个内存区域
- 每个区域包含：Guest 物理地址起始、大小、mmap 偏移、文件描述符
- 后端对每个区域调用 mmap，建立 GPA（Guest Physical Address）→ HVA（Host Virtual Address）映射表
- PRP 指针是 GPA，通过遍历映射表转换为 HVA 后直接访问
- 连接断开时统一 munmap 所有区域，关闭所有 FD

#### 3.5.6 与 NVMe/TCP 模式的对比

| 维度 | NVMe/TCP | vhost-user |
|------|----------|------------|
| 传输层 | TCP 网络 (端口4420) | Unix Socket + 共享内存 |
| QEMU 集成 | 需 Guest 内 nvme-tcp 驱动连接 | QEMU 直接模拟 PCIe NVMe 设备 |
| 数据拷贝 | TCP 收发需要多次内存拷贝 | PRP 直接访问共享内存，零拷贝 |
| 延迟 | 较高（TCP协议栈+网络开销） | 较低（共享内存+eventfd） |
| 命令封装 | NVMe/TCP PDU (ICReq/CapsuleCmd/H2CData等) | 原生 nvme_command_t (64字节) |
| 适用场景 | 跨主机/网络存储、远程访问 | 本地虚拟机存储加速、QEMU 集成 |

### 3.6 vfio-user NVMe PCIe后端协议层

#### 3.6.1 设计目标

vfio-user NVMe PCIe 后端使固件可以作为 QEMU 虚拟机的完整 PCIe NVMe 设备运行。与 vhost-user 基于 virtio 协议不同，vfio-user 模拟完整的 PCIe 设备（配置空间、BAR、MSI-X 中断、DMA），QEMU 通过 `vfio-user-pci` 设备连接本后端，虚拟机内使用标准 `nvme.ko` 驱动即可识别为真实 PCIe NVMe 设备。该模式更接近真实硬件行为，适用于 PCIe 驱动开发、NVMe 协议一致性测试和性能基准测试。

#### 3.6.2 协议层架构

```
┌─────────────────────────────────────────────────────────┐
│  QEMU 虚拟机 (Guest Linux)                                │
│  nvme.ko 驱动 ←→ PCIe 配置空间/BAR0 读写 ←→ MSI-X 中断    │
└──────────────────────────────┬──────────────────────────┘
                               │ Unix Socket (控制面)
                               │ + 共享内存 (DMA 数据面)
┌──────────────────────────────▼──────────────────────────┐

│  ┌─────────────────────────────────────────────────────┐ │
│  │  vfio_user_nvme.c                                    │ │
│  │  ┌──────────────┐  ┌──────────────┐  ┌───────────┐ │ │
│  │  │ 协议握手层    │  │ PCIe 设备模拟  │  │ MSI-X 管理 │ │ │
│  │  │ GET/DEVICE_* │  │ config/BAR0   │  │ eventfd   │ │ │
│  │  └──────┬───────┘  └──────┬───────┘  └─────┬─────┘ │ │
│  │         │                   │                   │       │ │
│  │  ┌──────▼───────────────────▼───────────────────▼─────┐ │
│  │  │         DMA 内存管理 (GPA→HVA 映射, mmap)           │ │
│  │  └──────────────────────┬──────────────────────────────┘ │
│  │                         │                                 │
│  │  ┌──────────────────────▼──────────────────────────────┐ │

│  │  └──────────────────────┬──────────────────────────────┘ │
│  └─────────────────────────┼────────────────────────────────┘
│                            │
│  ┌─────────────────────────▼────────────────────────────────┐
│  │  nvme_controller.c → ftl.c → nand.c                      │
│  └──────────────────────────────────────────────────────────┘
└─────────────────────────────────────────────────────────────┘
```

后端核心组件：
- **协议握手层**：处理 vfio-user 协议消息（GET_API_VERSION、DEVICE_GET_INFO、DMA_MAP 等），完成设备枚举和资源协商
- **PCIe 设备模拟**：维护 256 字节 PCIe 配置空间镜像和 64KB BAR0 镜像，响应 REGION_READ/WRITE
- **MSI-X 管理**：维护 MSI-X 向量表和 PBA，通过 eventfd 触发虚拟机中断
- **DMA 内存管理**：通过 DMA_MAP 消息接收 Guest 内存区域的文件描述符，mmap 建立 GPA→HVA 映射表
- **NVMe 命令处理**：检测门铃寄存器写入，从 Guest 内存 SQ 读取命令，调用 nvme_controller 处理，完成后写 CQ 并触发中断

#### 3.6.4 PCIe 配置空间模拟设计

后端维护 256 字节 PCIe Type 0 配置空间镜像（`pci_config[256]`），初始化时填充静态字段，运行时响应 QEMU 的 REGION_READ/WRITE。

**初始化字段：**

| 偏移 | 字段 | 初始值 | 说明 |
|------|------|--------|------|
| 0x00 | VID | 0x1B36 | Red Hat Vendor ID |
| 0x02 | DID | 0x0010 | Device ID |
| 0x04 | Command | 0x0006 | IO+Memory Space enable |
| 0x06 | Status | 0x0010 | Capabilities List |
| 0x08 | RID | 0x01 | Revision ID |
| 0x09 | Class Code | 0x010802 | NVMe Controller |
| 0x0C | Cache Line Size | 0x10 | 16 字节 |
| 0x0E | Header Type | 0x00 | Type 0 |
| 0x10 | BAR0 | 0xFFFF000C | 64-bit prefetchable, 64KB |
| 0x14 | BAR1 | 0x00000000 | BAR0 高 32 位 |
| 0x2C | SSVID | 0x1B36 | Subsystem Vendor ID |
| 0x2E | SSID | 0x0010 | Subsystem ID |
| 0x34 | Cap Pointer | 0x40 | MSI-X Capability 偏移 |
| 0x40 | MSI-X Cap ID | 0x11 | MSI-X Capability |
| 0x42 | Msg Ctrl | 0x8000 | Enable=1, 1 vector |
| 0x44 | Table Offset | 0x2000 | BAR0 内 MSI-X Table 偏移 |
| 0x48 | PBA Offset | 0x3000 | BAR0 内 PBA 偏移 |

**运行时读写处理：**
- QEMU 枚举时读取配置空间，后端返回镜像内容
- QEMU 写入 Command 寄存器（0x04）使能 Memory Space 后，BAR0 才可被 Guest 访问
- QEMU 写入 BAR0（0x10）分配 PCIe 地址，后端记录但不影响内部镜像（BAR0 内部偏移从 0 开始）
- MSI-X Capability 的 Msg Ctrl 写入可屏蔽/使能中断

#### 3.6.5 BAR0 空间管理设计

BAR0 为 64KB 内存空间，后端维护完整镜像（`nvme_regs[4096]` 用于控制器寄存器，门铃和 MSI-X 区域动态处理）。

**BAR0 布局：**

| 偏移 | 大小 | 区域 | 处理方式 |
|------|------|------|---------|
| 0x0000 | 4KB | NVMe 控制器寄存器 | 镜像数组，读写时调用 nvme_ctrl 接口 |
| 0x1000 | 4KB | Doorbell 寄存器 | 写触发命令处理，读返回当前尾/头指针 |
| 0x2000 | 4KB | MSI-X 向量表 | 镜像数组（16字节有效），QEMU 写入中断路由信息 |
| 0x3000 | 4KB | MSI-X PBA | 镜像数组（8字节），标记待处理中断 |
| 0x4000 | 48KB | 预留 | 读返回 0，写忽略 |

**寄存器读写分发：**
- 偏移 < 0x1000：NVMe 控制器寄存器，根据具体偏移调用 `nvme_ctrl_write_cc/aqa/asq/acq` 等接口
- 0x1000 ≤ 偏移 < 0x2000：Doorbell 寄存器，写时计算队列 ID，调用 `nvme_ctrl_sq_doorbell/cq_doorbell`，然后触发命令处理
- 0x2000 ≤ 偏移 < 0x3000：MSI-X 向量表，直接读写镜像
- 0x3000 ≤ 偏移 < 0x4000：MSI-X PBA，直接读写镜像

#### 3.6.6 MSI-X 中断模拟设计

MSI-X 中断通过 eventfd 机制实现：

1. **握手阶段**：QEMU 通过 DEVICE_SET_IRQS 消息传递 MSI-X eventfd（data_type=EVENTFD），后端保存到 `msix_evtfd`
2. **中断触发**：命令完成后，后端向 eventfd 写入 1（`write(msix_evtfd, &one, sizeof(uint64_t))`），QEMU 检测到 eventfd 可读后向 Guest 注入 MSI-X 中断
3. **PBA 更新**：触发中断前设置 PBA 对应位，Guest 驱动读取 PBA 后清除
4. **向量表**：QEMU 通过 BAR0 写 MSI-X 向量表（Message Address、Message Data、Vector Control），后端保存但不直接使用（中断路由由 QEMU 负责）

**当前配置：** 1 个 MSI-X 向量（VFIO_MSIX_VECTOR_COUNT=1），所有队列的完成中断共享同一向量。

#### 3.6.7 DMA 内存映射设计（GPA→HVA 转换）

vfio-user 后端通过 DMA_MAP 消息获取 Guest 物理内存区域，建立 GPA（Guest Physical Address）→ HVA（Host Virtual Address）映射：

**DMA_MAP 消息处理：**
1. QEMU 发送 DMA_MAP 消息，payload 包含 `vaddr`（Guest 物理地址）、`size`、`offset`（mmap 偏移）、`prot`（保护标志）
2. 文件描述符通过 SCM_RIGHTS 辅助数据传递（`recvmsg` + `CMSG_DATA`）
3. 后端调用 `mmap(NULL, size, prot, MAP_SHARED, fd, offset)` 映射到宿主虚拟地址
4. 映射信息保存到 `dma_regions[]`、`dma_mappings[]`、`dma_fds[]` 数组，最多 16 个区域

**GPA→HVA 转换：**
```c
void *gpa_to_hva(uint64_t gpa) {
    for (i = 0; i < dma_region_count; i++) {
        if (gpa >= dma_regions[i].vaddr &&
            gpa < dma_regions[i].vaddr + dma_regions[i].size) {
            return (uint8_t *)dma_mappings[i] +
                   (gpa - dma_regions[i].vaddr);
        }
    }
    return NULL;
}
```

**PRP 数据传输：**
- NVMe 命令中的 PRP1/PRP2 是 Guest 物理地址
- Read 命令：后端从 FTL/NAND 读取数据，通过 GPA→HVA 转换后写入 Guest 内存
- Write 命令：后端通过 GPA→HVA 转换从 Guest 内存读取数据，写入 FTL/NAND
- PRP 列表：PRP2 页对齐时指向 PRP 条目列表，需遍历列表获取所有数据页地址

**清理：** 连接断开时，遍历所有区域调用 `munmap`，关闭所有 FD。

#### 3.6.8 NVMe 寄存器读写处理流程

**读寄存器（REGION_READ → BAR0 偏移 < 0x1000）：**
1. QEMU 发送 REGION_READ，指定 region_index=1（BAR0）、offset、count
2. 后端根据 offset 判断寄存器类型
3. 从 `nvme_regs[]` 镜像读取，或动态计算（如 CSTS.RDY 位）
4. 构造 REGION_READ 回复，携带读取的数据

**写寄存器（REGION_WRITE → BAR0 偏移 < 0x1000）：**
1. QEMU 发送 REGION_WRITE，携带写入数据
2. 根据 offset 分发：
   - CC (0x14)：调用 `nvme_ctrl_write_cc()`，若 CC.EN 从 0→1 则置 CSTS.RDY=1
   - AQA (0x24)：调用 `nvme_ctrl_write_aqa()`
   - ASQ (0x28/0x2C)：调用 `nvme_ctrl_write_asq()`，保存 Admin SQ 物理地址
   - ACQ (0x30/0x34)：调用 `nvme_ctrl_write_acq()`，保存 Admin CQ 物理地址
   - 其他：更新镜像
3. 回复 REGION_WRITE 确认

**写门铃（REGION_WRITE → BAR0 偏移 ≥ 0x1000）：**
1. offset 在 0x1000-0x1FFF 范围
2. 计算队列 ID：`qid = (offset - 0x1000) / 8`
3. 偶数偏移（0x1000+qid*8）：SQ Tail Doorbell，调用 `nvme_ctrl_sq_doorbell(qid, value)`，触发命令处理
4. 奇数偏移（0x1004+qid*8）：CQ Head Doorbell，调用 `nvme_ctrl_cq_doorbell(qid, value)`，更新 CQ 头指针

#### 3.6.9 命令处理流程

```
Guest nvme.ko 驱动
    |
    | 写 SQ Tail Doorbell (BAR0 + 0x1000 + qid*8)
    ▼
vfio-user 后端 REGION_WRITE 处理
    |
    | 计算 qid，调用 nvme_ctrl_sq_doorbell()
    ▼
从 Guest 内存 SQ 读取 nvme_command_t (64字节)
    |
    | SQ 地址 = ASQ + (tail * 64)，通过 GPA→HVA 转换
    ▼
判断队列类型
    |
    ├─ Admin 队列 (qid=0) → nvme_ctrl_process_admin_cmd()
    │     ├─ Identify → 填充数据到 PRP 指向的 Guest 内存
    │     ├─ Get Log Page → 填充 SMART/健康日志
    │     ├─ Set Features → 配置队列数/中断/AER
    │     ├─ Create I/O CQ/SQ → 创建 I/O 队列
    │     └─ Keep Alive → 保活
    │
    └─ I/O 队列 (qid>0) → nvme_ctrl_process_io_cmd()
          ├─ Read → ftl_read() → 通过 PRP 写入 Guest 内存
          ├─ Write → 通过 PRP 从 Guest 内存读数据 → ftl_write()
          ├─ Write Zeroes → ftl_write() 写零
          ├─ Flush → 同步返回
          └─ Dataset Management → ftl_trim()
    |
    ▼
构造 nvme_completion_t (16字节)
    |
    ▼
写入 Guest 内存 CQ
    |
    | CQ 地址 = ACQ + (head * 16)，通过 GPA→HVA 转换
    | 更新 phase tag (CQ 头指针翻转时翻转)
    ▼
写 MSI-X eventfd (触发中断)
    |
    ▼
Guest nvme.ko 驱动从 CQ 读取完成条目
```

#### 3.6.10 与 nvme_controller 的集成方式

vfio-user 后端与 nvme_controller 模块通过以下接口集成：

| 集成点 | nvme_controller 接口 | 调用时机 |
|--------|---------------------|---------|
| 控制器初始化 | `nvme_ctrl_init()` | 固件启动时，vfio-user 初始化之前 |
| CC 寄存器写 | `nvme_ctrl_write_cc(value)` | Guest 写 CC 寄存器 |
| AQA 寄存器写 | `nvme_ctrl_write_aqa(value)` | Guest 写 AQA 寄存器 |
| ASQ 寄存器写 | `nvme_ctrl_write_asq(value, is_high)` | Guest 写 ASQ 寄存器（64位，分两次写） |
| ACQ 寄存器写 | `nvme_ctrl_write_acq(value, is_high)` | Guest 写 ACQ 寄存器（64位，分两次写） |
| SQ 门铃 | `nvme_ctrl_sq_doorbell(qid, value)` | Guest 写 SQ Tail Doorbell |
| CQ 门铃 | `nvme_ctrl_cq_doorbell(qid, value)` | Guest 写 CQ Head Doorbell |
| Admin 命令处理 | `nvme_ctrl_process_admin_cmd(cmd, cpl)` | 从 Admin SQ 读取命令后 |
| I/O 命令处理 | `nvme_ctrl_process_io_cmd(cmd, cpl)` | 从 I/O SQ 读取命令后 |
| 控制器事件处理 | `nvme_ctrl_process()` | 主循环中周期性调用 |

**数据流向：**
- vfio-user 后端负责 PCIe 层面的协议处理（配置空间、BAR0、MSI-X、DMA 映射）
- nvme_controller 负责 NVMe 协议层面的命令处理（Admin/I/O 命令、队列管理、寄存器状态）
- 两者通过寄存器写接口和命令处理接口解耦，vfio-user 后端将 Guest 的 MMIO 写转换为 nvme_controller 的函数调用

### 4.4 GC触发流程

```
ftl_alloc_phy_page() 分配新页
    │
    ▼
当前写入块是否有空闲页？
    │
    ├─ 有 → 直接分配当前页，cur_write_page++
    │
    └─ 无 → 选择新空闲块
              │
              ▼
         空闲块数量是否低于阈值？
              │
              ├─ 否 → 选择擦写次数最少的空闲块
              │
              └─ 是 → 触发GC ftl_trigger_gc()
                        │
                        ├─ 根据GC算法选择victim块
                        ├─ 遍历victim块有效页
                        │     ├─ 读取有效页数据
                        │     └─ 写入新空闲块
                        ├─ 更新L2P映射
                        ├─ 擦除victim块
                        └─ gc_count++
```

### 5.2 PLP掉电保护设计

**快照文件结构**：
```

│ ftl_meta_header_t (32字节)      │
│   magic="FTL1"                  │
```

**保存策略**：
- 定期保存：主循环每5000次循环保存一次
- 退出保存：固件正常退出前保存一次
- 异步保存：保存操作不阻塞主机I/O（当前为同步，可优化为异步）

- 启动时自动尝试恢复
- 快照不存在 → 全新初始化
- 快照校验失败 → 记录错误，全新初始化（可配置为拒绝启动）
- 快照校验通过 → 恢复L2P映射和统计信息

### 5.3 ECC纠错设计

**(7,4)汉明码原理**：
- 4位数据(d0,d1,d2,d3) + 3位校验(p1,p2,p4) = 7位码字
- p1校验位置1,3,5,7：p1 = d0⊕d1⊕d3
- p2校验位置2,3,6,7：p2 = d0⊕d2⊕d3
- p4校验位置4,5,6,7：p4 = d1⊕d2⊕d3
- 解码时计算校正子(syndrome) = (s4,s2,s1)，非零时指向错误位置(1-7)
- 可纠正1位错误，检测2位错误

**整页ECC实现**：
- 对4096字节数据，逐字节计算汉明码，异或汇总为32位ECC值
- 写入时：计算ECC → 存入OOB.ecc字段
- 读取时：重新计算ECC → 与OOB存储值比较
  - 相同：无错误
  - 不同：逐位翻转尝试（暴力法定位1位错误），翻转后ECC匹配则纠正成功
  - 1位翻转无法匹配：多位错误，返回UNCORRECTABLE

**纠错统计**：
- ecc_corrected_count：已纠正的1位错误次数
- ecc_uncorrectable_count：无法纠正的多位错误次数

## 6. 性能优化

### 6.1 已实施的优化

| 优化项 | 优化前 | 优化后 | 提升 |
|--------|--------|--------|------|
| NAND层mmap优化 | fseek+fwrite/fread，每次读写系统调用 | mmap(MAP_SHARED)+memcpy，内核异步刷盘 | 写性能提升13倍 |
| NVMe/TCP预分配缓冲区 | 每个I/O命令malloc/free缓冲区 | 预分配1MB读/写缓冲区，零内存分配 | 写性能再提升10% |
| I/O路径日志优化 | 每个命令LOG_INFO输出 | 只保留错误日志，I/O路径无日志 | 减少系统调用开销 |
| Write Zeroes优化 | 每次memset(4K)零缓冲区 | 静态零缓冲区，无需重复初始化 | 减少CPU开销 |
| NAND写入fflush | 每次nand_page_write都fflush强制刷盘 | 去掉fflush，nand_deinit时统一flush | 写入性能3-5倍 |
| 日志级别 | 默认INFO，I/O路径频繁输出 | 默认WARN，--debug/--trace参数控制 | I/O路径开销降低 |
| L2P映射查找 | - | 数组直接索引，O(1) | 映射查找无开销 |
| 编译输出目录 | build/（VMware HGFS共享目录） | /tmp/ftl-firmware-build（本地文件系统） | 解决file too short链接错误 |

### 6.2 性能数据

**测试环境**: VMware Linux虚拟机, fio 3.36, 4K块大小, iodepth=1, runtime=5s

| 优化阶段 | 顺序读 | 顺序写 | 写IOPS | 写性能提升 |
|---------|-------|-------|--------|-----------|
| 基线版本(fwrite/fread) | ~7.0 MB/s | ~2.5 MB/s | ~625 | 1x |
| NAND层mmap优化 | ~6.8 MB/s | ~32.5 MB/s | ~8115 | 13x |
| NVMe/TCP协议栈优化 | **6.9 MB/s** | **35.8 MB/s** | **~9165** | **14.3x** |

**性能优化成果**:
- 写性能总体提升 **14.3倍**（2.5 → 35.8 MB/s）
- 写IOPS提升 **14.7倍**（625 → 9165）
- 读性能基本持平（瓶颈在NVMe/TCP协议栈单线程select模型）

> 注：当前为单线程select模型，读性能受架构限制。生产级SSD固件采用多队列+异步I/O+硬件DMA，性能可达GB/s级别。

| P1 | FTL映射表缓存 | 随机读性能提升 | 热点L2P表项缓存到内存 |
| P1 | GC异步化 | 写延迟降低 | GC在后台线程执行，不阻塞写路径 |
| P2 | 大页支持 | 吞吐量提升 | 支持8K/16K页大小，减少元数据开销 |
| P2 | CPU亲和性 | 延迟稳定性提升 | 绑定中断和处理线程到特定CPU核心 |
| P2 | 写入缓冲 | 写性能提升 | 先写入DRAM缓存，后台刷入NAND（需PLP保护） |

- test_multi_page_rw：多页连续写入→全部读取→数据一致

- test_snapshot_not_exist：加载不存在的快照返回错误
- test_trim_recovery：写入→TRIM→保存快照→恢复→TRIM后无法读取原始数据

```bash
sudo nvme dsm /dev/nvme0n1 --ad 1 --blocks=100,16
```
