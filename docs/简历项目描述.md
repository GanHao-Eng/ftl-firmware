## 项目名称

**企业级 SSD 固件模拟器（ftl-firmware）**

## 项目角色

独立开发者 / 项目主导

## 项目时间

2026.06 - 2026.08

## 项目简介

从零设计并实现一个企业级 SSD 固件模拟器，完整模拟 NAND 闪存、FTL 闪存转换层、NVMe 控制器及 NVMe/TCP 目标端协议栈。可与 Linux 内核 nvme-tcp 驱动真实对接，通过 nvme-cli、fio 等标准工具验证功能与性能。

## 技术栈

- **语言**：C（C99）
- **协议**：NVMe 1.4、NVMe/TCP（TCP 传输层）
- **核心技术**：FTL（页映射/块映射/混合映射）、GC 垃圾回收（6 种算法）、磨损均衡、WAL 日志、TRIM/Dataset Management
- **工具**：GCC、Make、nvme-cli、fio、Wireshark/tcpdump、GitHub Actions CI
- **平台**：Linux（Ubuntu，内核 7.0）

## 核心工作与成果

### 1. NVMe/TCP 目标端协议栈实现（核心亮点）

- 从零实现完整 NVMe/TCP 协议栈：IC 握手 → Connect → Admin 队列 → I/O 队列
- 与 Linux 内核 7.0 nvme-tcp 驱动完整对接，支持 `nvme connect/list/read/write` 等标准命令
- 实现 CapsuleCmd/CapsuleResp/C2HData/H2CData/R2T 等 PDU 类型
- 支持多队列（Admin + 2 个 I/O 队列），队列 ID 从 Connect inline data 提取
- **调试深度**：通过 dmesg 报错和 tcpdump 抓包，逐步对齐协议格式，解决 CapsuleResp phase bit、Identify Controller 字段偏移、LBAF 布局、Get Log Page 与 I/O Read opcode 冲突等 11 个关键协议问题

### 2. FTL 闪存转换层

- 实现页映射、块映射、混合映射三种映射模式
- 实现 6 种 GC 算法：Greedy、Cost-Benefit、CAT、Windowed、d-Choices、FRA，并完成性能对比测试
- 实现动态/静态磨损均衡、坏块管理、WAL 日志恢复
- 实现 TRIM/Dataset Management、Write Zeroes 命令
- FTL 层单元测试 25 项全部通过，覆盖初始化、单页/多页读写、覆盖写、TRIM、GC 触发

### 3. NAND 闪存模拟层

- 模拟 TLC NAND 闪存：128 块 × 256 页 × 4KB，支持坏块注入
- 实现页读写、块擦除、磨损计数
- 支持 ECC 纠错算法框架（LDPC/BCH）

### 4. 工程化与质量保障

- 模块化 5 层架构：NAND 层 → FTL 层 → NVMe 控制器层 → NVMe/TCP 传输层 → 管理层
- Doxygen 风格函数注释，关键协议字段标注 NVMe 规范偏移
- GitHub Actions CI：自动编译 + 单元测试 + GC 基准测试
- 调试文档：11 个协议踩坑记录 + 调试方法论，可作为团队知识沉淀

## 面试可展开话题

1. **NVMe/TCP 协议调试**：CapsuleResp 为什么不能设 phase bit？Connect QID 在哪里？Get Log Page 和 I/O Read opcode 都是 0x02 怎么区分？
2. **FTL GC 算法**：Greedy vs Cost-Benefit 的 trade-off？CAT 算法的三个维度？写放大系数（WAF）怎么计算？
3. **磨损均衡**：动态磨损均衡和静态磨损均衡的区别？什么时候触发静态磨损均衡？
4. **映射模式**：页映射、块映射、混合映射的优缺点？为什么企业级 SSD 用页映射？
5. **NVMe 队列机制**：Admin 队列和 I/O 队列的关系？SQ/CQ/Doorbell 怎么配合？
