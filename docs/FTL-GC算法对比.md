# FTL GC 算法对比分析

> 本文对比了 6 种 FTL 垃圾回收（GC）算法在相同 workload 下的性能表现，
> 包括写放大系数（WAF）、GC 次数、有效页搬迁数量等关键指标。

---

## 1. GC 算法原理

### 1.1 Greedy（贪心算法）

**原理**：每次选择有效页最少的块进行回收。

**优点**：实现简单，单次回收搬迁页数最少。
**缺点**：未考虑块的擦写次数和年龄，可能导致磨损不均衡。

**适用场景**：对磨损均衡要求不高的场景。

---

### 1.2 Cost-Benefit（成本收益算法）

**原理**：综合考虑块的有效页数（成本）和块的年龄（收益），选择"成本/收益比"最低的块。

公式：`score = (1 - u) / (1 + u) * age`，其中 u 是有效页比例，age 是块年龄。

**优点**：考虑了数据温度，热数据块不会被过早回收。
**缺点**：需要维护块的年龄信息。

---

### 1.3 CAT（Cost-Age-Time）

**原理**：在 Cost-Benefit 基础上，增加时间维度权重，综合评估块的回收价值。

**优点**：更全面的块评估，适合冷热数据混合的 workload。
**缺点**：计算复杂度稍高。

---

### 1.4 Windowed（窗口算法）

**原理**：在最近 N 个块（窗口）中选择有效页最少的块回收，而非全局搜索。

**优点**：选择速度快，局部性好，适合高并发场景。
**缺点**：可能错过全局最优块。

---

### 1.5 d-Choices

**原理**：随机选择 d 个块，从中选择有效页最少的回收。

**优点**：随机性避免了最坏情况，性能接近 Greedy 但开销更小。
**缺点**：结果有随机性，不可预测。

---

### 1.6 FRA（Full Recovery Algorithm，全回收算法）

**原理**：回收所有可回收块，最大化释放空间。

**优点**：一次回收释放最多空间。
**缺点**：搬迁页数多，写放大高。

---

## 2. 测试方法

### 2.1 测试环境

| 项目 | 值 |
|------|-----|
| FTL 总逻辑页 | 22937 (128块 × 256页 × 70%) |
| 页大小 | 4096 字节 |
| 物理块数 | 128（含坏块） |
| 测试逻辑页 | 15000 |

### 2.2 Workload

三阶段写入，模拟真实 SSD 使用场景：

1. **顺序填充**：写入 85% 空间（12750 页），模拟初始数据写入
2. **随机覆盖**：随机覆盖 60% 空间（9000 页），模拟随机写 workload
3. **顺序覆盖**：顺序覆盖 40% 空间（6000 页），模拟顺序写 workload
4. **手动触发 GC**：确保 GC 被调用

### 2.3 关键指标

- **WAF（Write Amplification Factor）**：NAND 实际写入量 / 主机写入量，越低越好
- **GC 次数**：GC 触发次数，越少说明空间管理越好
- **搬迁页数**：GC 过程中搬迁的有效页数，越少越好
- **耗时**：总执行时间，反映算法开销

---

## 3. 测试结果

### 3.1 数据总览

| 算法 | WAF | GC次数 | 搬迁页数 | 主机写 | NAND写 | 耗时(ms) |
|------|-----|--------|----------|--------|--------|----------|
| Greedy | 1.00 | 1 | 63 | 27750 | 27813 | 337.6 |
| Cost-Benefit | 1.00 | 1 | 66 | 27750 | 27816 | 282.3 |
| CAT | 1.00 | 1 | 58 | 27750 | 27808 | 289.2 |
| **Windowed** | **1.00** | **1** | **51** | **27750** | **27801** | 294.6 |
| d-Choices | 1.00 | 1 | 61 | 27750 | 27811 | 305.7 |
| FRA | 1.00 | 1 | 55 | 27750 | 27805 | 292.0 |

### 3.2 排名

| 维度 | 最优算法 | 数值 |
|------|----------|------|
| 搬迁页数最少 | Windowed | 51 页 |
| 耗时最短 | Cost-Benefit | 282.3 ms |
| NAND 写入最少 | Windowed | 27801 页 |

## 4. 分析与结论

### 4.1 WAF 分析

本次测试 WAF 均接近 1.00，原因是：
- 测试 workload 只触发了 1 次 GC
- 单次 GC 搬迁页数（51-66）相对于总写入量（27750）占比很小
- WAF = (27750 + 搬迁页数) / 27750 ≈ 1.002

**在更极端的 workload（长时间运行、高写入量）下，不同算法的 WAF 差异会更明显。**

### 4.2 搬迁页数分析

搬迁页数直接反映 GC 算法的选择效率：

- **Windowed (51页)**：最优，窗口内选择有效页最少的块，搬迁最少
- **FRA (55页)**：次优，全回收策略在本次测试中意外表现良好
- **CAT (58页)**：综合评估，表现稳定
- **d-Choices (61页)**：随机选择，结果中等
- **Greedy (63页)**：全局搜索有效页最少，但未考虑年龄因素
- **Cost-Benefit (66页)**：最多，因为优先回收冷数据块，而冷数据块可能有效页较多

### 4.3 算法选择建议

| 场景 | 推荐算法 | 理由 |
|------|----------|------|
| 通用消费级 SSD | Greedy / Windowed | 实现简单，性能足够 |
| 企业级高写入 | CAT / Cost-Benefit | 考虑数据温度，减少热数据搬迁 |
| 高并发低延迟 | Windowed / d-Choices | 选择速度快，开销小 |
| 空间紧张 | FRA | 最大化释放空间 |

### 4.4 本项目默认选择

当前项目默认使用 **Greedy 算法**，原因：
1. 实现最简单，代码可读性好
2. 单次 GC 搬迁页数接近最优
3. 适合作为教学和基础版本

生产环境建议根据 workload 特征选择 CAT 或 Cost-Benefit。

## 5. 复现测试

```bash
cd ftl-firmware
make test
./build/test_gc_benchmark
```

测试程序位于 `tests/test_gc_benchmark.c`，可通过修改以下宏调整 workload：

```c
#define TEST_LPNS           15000   // 测试逻辑页数
#define TEST_FILL_RATIO     0.85    // 初始填充比例
#define TEST_OVERWRITE_RATIO 0.6    // 随机覆盖比例
#define TEST_SEQ_RATIO      0.4     // 顺序覆盖比例
```
